# Daily autopilot (runs every day from .github/workflows/opencode-daily.yml, no Hark)
Hark (the supervisor) is out of usage. This repo must keep the IA (@ia.unfolds) mystery Shorts channel going on its own: 2 Shorts posted every IST day, at 13:15 IST and 21:30 IST only (YouTube + X via Buffer). Never Instagram. Never post at any other time.
Each run, in order. Keep each run small and safe; build once, then later runs only check and fix.
1. Read the newest reports/<date>.json and the last daily-shorts run (GitHub API with $GH_TOKEN). For every Short that failed shortqa and has no healed artifact, run daily/heal_artifact.sh. Fix the root cause in code when a NEW kind of failure appears (extend daily/heal.py, plate_guard, scenes). Never loosen shortqa thresholds.
2. Posting (build once, then keep it working): write daily/post_slot.py, called by .github/workflows/post-slots.yml at 13:15 and 21:30 IST with env BUFFER_API_KEY. It picks the next unposted Short whose qa.json has post=true (newest daily-shorts artifacts and healed-<slug> artifacts, plus finals in out/), hosts the mp4 at a public URL Buffer can fetch (e.g. litterbox.catbox.moe 72h upload; check the URL returns video/mp4), and schedules it with the Buffer GraphQL API (https://api.buffer.com, header "Authorization: Bearer $BUFFER_API_KEY"). Port the logic from tools/post_yt_x/post.py (it ran on a proxy that injected the key, so add the header; keep its duplicate guard and slot guard). Use the packaging files yt_title.txt, yt_desc.txt, x_text.txt, x_thread.json, AI_TAG false. Record each post in reports/posted.csv (date, slot, slug, buffer ids) and never post a slug twice. Alternate narrator_m / narrator_f across adjacent slots when possible. If BUFFER_API_KEY is empty, exit 0 with a clear log line. Add a --dry-run and test it in this run.
3. If no Short is ready for tomorrow's two slots, make sure daily-shorts will produce them (fix whatever stops it).
4. Apply tasks/karpathy rules from AGENTS.md. Write tasks/RESULT.md (append a dated section: what you did, real test numbers, what is still broken).
You cannot edit .github/workflows/. If a workflow change is needed, write it to tasks/WORKFLOW_PATCH/ and explain it in RESULT.md.
